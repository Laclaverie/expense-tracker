# Demo showcase — design (B37)

Date: 2026-11-01. Status: approved in conversation, awaiting spec review.

## Goal

Show the app to people — live (screen share, a friend's PC) and on the public README — with made-up data that
tells a clear story and is the same every time. Not a dev tool (the existing demo database stays that), not an
in-app "try the demo" button.

Success:
- `demo.bat` gives the same starting state every run, in under a minute, without touching the real database.
- One documented 7-stop walkthrough (`docs/13-demo.md`) that someone other than the owner can follow.
- README images regenerated by one command from the same stop list; they never show a real value.
- Two personas, each showing something the other can't.

## Constraints

- Privacy rules of `CLAUDE.md`: synthetic data only, encrypted database (public demo password), never the real
  database folder.
- Bank fixtures written by `demo:fixtures` stay byte-identical (they come from the couple).
- Desjardins is the only bank: both personas bank there.
- Only demo runs and shot tests may change the app's clock.

## Personas

`packages/demo/lib/src/persona.dart` holds one persona as top-level constants read by `household.dart`. It becomes
a `Persona` value (shops, habits, bills, trips, one-offs, income rules, accounts, seed, date span) and
`liveHousehold(Persona)`.

| id | Who | What it shows |
|----|-----|---------------|
| `couple` (main) | Current household: two adults renting in Montréal, no car, two cards, salaries | The full story below; README images |
| `freelancer` | One person, apartment downtown (Ville-Marie), no car (STM pass, BIXI, Communauto sometimes), Desjardins account + card | Irregular income: client deposits of uneven size and timing (some months near 0, some about 3×), quarterly tax installments (`Cadence.quarterly`), coworking and software subscriptions, savings moved in good months. Balances over time, trends with uneven months, a yearly target, anomalies |

Both live 2024-10-21 → 2026-10-20 (`lifeStart` / `lifeEnd`), seeded (`dice.dart`): same output every run.

## Show state

`packages/demo/lib/src/showcase.dart`: `fillShowcaseDatabase(db, persona)` next to `fillDemoDatabase` (dev state
unchanged — tests and `ui-probe` rely on it).

- Every statement imported through the real plug-in, **except the last card statement period**, held back and
  written as an AccèsD card CSV export by `src/desjardins/card_csv.dart` (13 columns, card name + `**** 0000`,
  days oldest first, a day's lines newest first — layout in `banks/lib/src/desjardins/csv/reader.dart`). Demo
  writes words, not PDFs: the CSV is what makes a live drag & drop possible.
- Everything before the held-back period reviewed; the CSV's lines are mostly known merchants (one-click
  suggestions, bulk confirm) plus a couple never categorized, so review has work and can end at 0.
- Couple keeps the missing June 2026 account statement (bell: coverage story). Each persona declares its own
  targets, left-to-review merchants and held-back period.
- CLI `dart run demo:showcase <folder> [--persona couple|freelancer]` writes `expenses.sqlite` (refuses an existing
  file, like `demo:database`) and `releve-carte.csv`.

## App clock

The app calls `DateTime.now()` in 9 places (`app_state.dart`, dashboard, stats, targets, notifications, accounts,
dev copy dialog). Shown after 2026-10-20 the demo would have an empty current month and every statement "due".

`apps/desktop/lib/clock.dart`: `DateTime appNow()`. `EXPENSES_TODAY=YYYY-MM-DD` overrides it, read only together
with `EXPENSES_DB_DIR` (as `EXPENSES_DB_PASSWORD`); otherwise the real time. Every app `DateTime.now()` goes
through it, except the dev-copy file name timestamp. Demo runs use 2026-10-22.

## demo.bat

Root, next to `run-desktop.bat` (uses `tools\env.bat`):
1. `demo.bat [couple|freelancer]` (default `couple`).
2. Wipes and recreates `%LOCALAPPDATA%\expense-tracker\demo\<persona>` (never the real database folder).
3. Runs `demo:showcase` there.
4. Opens Explorer on the folder (the CSV to drag).
5. Starts the last release build with `EXPENSES_DB_DIR`, `EXPENSES_DB_PASSWORD=demo database password`,
   `EXPENSES_TODAY=2026-10-22`; builds first if there is none, like `run-desktop.bat`.

## The walkthrough (couple)

| # | Stop id | Screen | Point |
|---|---------|--------|-------|
| 1 | `dashboard` | Password screen → dashboard | The month at a glance, target bars, bell (due statement, anomaly) |
| 2 | `import` | Import: drop `releve-carte.csv` | No typing; coverage grid fills the card gap |
| 3 | `review` | Review | Reason per line, one-click suggestions, bulk confirm, ends at 0 |
| 4 | `categories` | Statistics → categories → Groceries | Shares without rent; per-store cards |
| 5 | `recurring` | Statistics → recurring | Subscriptions, Hydro every 2 months, rent: fixed costs per month |
| 6 | `trends` | Statistics → trends / compare | This month vs last; the anomaly explained |
| 7 | `search` | Ctrl+K | Any merchant, instantly |

Freelancer tour (doc only, no README images): balances, trends with uneven income, yearly target, anomalies.

## Screenshot generator

- `apps/desktop/test/demo/stops.dart`: the stops above (id + how to reach it with finders/keys).
- `apps/desktop/test/demo_shots_test.dart`: skipped unless `DEMO_SHOTS_OUT` is set (`test-all` and CI skip it).
  Showcase database in memory (couple), Segoe UI loaded as in `screens_smoke_test.dart`, 1440×900, English
  (`DEMO_SHOTS_LOCALE=fr` for French), clock fixed at 2026-10-22. The import stop feeds the CSV text through the
  entry a drop uses. Writes `demo-<n>-<id>.png`.
- `tools\demo-shots.ps1`: runs it with `DEMO_SHOTS_OUT=docs\images`. The owner reruns it when the UI changes,
  looks at the images, commits them.
- Drift guard (normal test, always runs): every stop id in `stops.dart` appears in `docs/13-demo.md`.

## Docs

- `docs/13-demo.md`: setup, the 7 stops (what to click, what to say), the freelancer tour, how to regenerate
  images.
- README: "See it first" section near the top, 3–4 couple images, "run `demo.bat` to try it without your own
  statements".
- `CLAUDE.md` status and layout, roadmap B37 → `12-done.md` when finished.

## Testing

- `demo`: the CSV reads back with the real CSV reader (lines and dates equal the held-back period); both personas'
  statements read back with the real plug-in; showcase database fills for both personas; fixtures unchanged
  after the `Persona` refactor (compare `demo:fixtures` output).
- Desktop: `appNow()` override only with `EXPENSES_DB_DIR`; smoke test still passes; drift guard.
- Visual check: `demo.bat` both personas, walk the 7 stops on the release build.

## Out of scope

In-app demo button, more banks or a third persona, PDF writing, shots in CI, a freelancer image set.
